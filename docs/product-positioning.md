# 产品起点与用户旅程

本稿记录当前已交付的研究起点与接续行为，以及尚未完成的后续项。用户需求与预期产物仍是产品假设，尚未经过真实用户访谈或转化数据验证，不代表市场结论、专家认可或科研有效性背书。

Scientific Agent 是面向研究学生与研究人员的科研讨论工作台：从兴趣、已有论文或明确问题出发，帮助用户形成有来源、可审阅、可修改、可导出的研究方案。中央对话负责解释与推进；论文原文、比较条件、调用记录和质量检查按需展开。本轮交付终点是研究方案，不是执行实验、产出论文或证明创新。

## 三类用户，一个连续工作区

起点代表本次任务，不是给用户固定贴标签；同一用户可随时改方向、带入论文或跳到已有问题。不要求所有人从第一阶段重走。

| 用户与起点 | 首次需要提供什么 | 本次引导的预期产物 | 下一步如何发生 |
|---|---|---|---|
| 第一次研究的学生：带我入门 | 一点兴趣或应用，也允许回答“还不确定”；只追问影响当前选择的一两个条件 | 少量容易理解的切入方向，说明各自想回答什么、需要哪些资料 | 用户选择或调整范围，再明确确认是否检索；不直接生成完整课题 |
| 带论文的研究生：从论文开始 | 用现有上传入口选择 PDF／文本；可补充想理解或比较的重点 | 基于实际可读摘要／片段的阅读梳理：研究对象、方法、局限与尚不清楚的问题，附来源范围 | 先解释概念或比较已有论文，再讨论候选研究问题；已有可读资料时复用，不默认再检索 |
| 已有问题的研究者：讨论我的问题 | 自己的问题表述及已有条件；未提供的信息保持未知 | 问题范围与可回答性的梳理，必要时形成可明确采纳的候选问题 | 用户确认具体问题后选择方法、准备方案；若项目已有有效正式问题，可直接讨论方案，不重新选题 |

“我有方向，想找研究切入点”保留为第四张任务入口，服务上述用户中尚未携带论文的人。它先比较切入思路与所需资料，再复用原有检索范围确认和报告交付，不创建第四套科研流程。入口展示的是本次讨论目标，不保证每次模型回复都已达到相应科研质量。

## 本轮已交付的三项改进

1. **论文有明确起点。** 首屏提供入门、方向、论文、已有问题四张任务卡，手机保留副说明。选择后展示本次预期产物与待提供资料；论文入口的“选择论文”使用已有文件选择与附件恢复逻辑。选择起点或文件都不创建项目、不调用模型，实际发送才进入原有保存与上传流程。
2. **已有问题先确认，再衔接方案。** 起点进入问题讨论，不直接要求完整方案；已有正式问题则依当前材料继续设计。候选问题仍由用户采纳，过期依据仍需复核，不能把输入的一句话静默升级为正式问题。
3. **中央对话给出一项当前主行动。** 已有候选先查看、已有方案先打开，缺问题或资料时提供相应准备入口，暂停时回到自由输入。主行动说明接下来会做什么；完整六步默认折叠在“更换当前任务”中，审计、来源与版本仍可查阅。展开路线或切换任务不自动执行研究操作。

## 当前交付与后续项

**已交付：起点能启动，已有工作能接续。** 复用 `conversation-home.js` 的起点设置、`chooseFile`、附件持久化、`chooseReply`、`preparePlanInput` 和现有 `research-route`。采用四张紧凑起点卡、可编辑输入和一块预期产物提示，不另建身份问卷或用户分群状态。起点随草稿恢复；有用户草稿时切换须明确确认，取消不改原有内容与设置，确认追加也不沿用旧的检索或方案生成意图。完整路线使用原有六步数据，状态来自后端和已保存材料，不能由前端“已进入阶段”推断完成。

**已交付：主行动与科研细节分层展示。** 复用现有方案预览、材料侧栏、报告、引用范围和交付检查。继续保留错误、降级和失败重试入口；用户先看当前可做的事，完整配置、来源审计与科学比较条件按需展开。部分功能未配置不能误拦已配置功能，规则与离线案例保持可用。

**后续：中央检索报告摘要卡。** 当前检索任务显示真实状态、数量及打开报告的操作，报告摘要仍在折叠详情中。本轮没有新增中央摘要卡，不能将“报告已保存”描述成用户已在中央对话读到完整研究现状。后续可复用已有摘要并提供衔接阅读或问题讨论的入口，不默认再检索。

**P1：验证首份产物是否有用。** 后续用获得同意的用户反馈检验三条路径。关注能否不靠指导完成首次有意义发送、是否理解产物的依据范围、能否找到下一步、是否在正式采纳前修改过问题或方案。暂不新增付费埋点、营销漏斗或渠道投放；现有本地行为测试只证明功能，不能替代用户验证。

## 行为边界

- 四个起点均能设置对应讨论目标与准备提示；切换前保留未发送草稿，取消不会改设置、附件或生成元数据。
- 论文起点使用同一个上传实现；未发送、取消文件选择、刷新恢复、上传失败均不会产生额外项目或静默重发。
- 已有问题起点不会直接请求完整方案；方案始终明确关联用户选择的有效问题，采纳与生成是不同操作。
- 阅读或现状整理优先复用已有可读材料；选择步骤只改变讨论任务，检索仍需明确确认范围。
- 对话保留自由输入和改方向能力；推荐动作不能覆盖草稿、继承无关方案请求或自动采纳材料。
- 390px 与桌面均可看到输入与发送入口；起点副说明保留，流程详情默认折叠，研究材料关闭后回到原对话位置。

## 现有依据与限制

已审查 `web/static/conversation-home.js`、`conversation-home.css`、`research-flow.js`，以及前端产品行为、科研路线、指导和本地交付相关测试。新增 Node 行为检查已覆盖四起点设置、草稿取消与追加、已有材料的主行动分支；实际页面已检查四起点选择、准备提示、草稿刷新恢复及桌面／390px 输入可用性。原有测试继续覆盖只读配置、问题关联、显式采纳、来源变化和步骤不触发执行。

实际临时应用还走通了“已有问题 → 候选确认 → 方案准备 → 草案审阅 → 明确采纳 → MD 导出”，并验证了正式方案的修订草案优先审阅、缺少正式问题时返回问题讨论的恢复路径。规则模式只提供待完善讨论稿；该验收证明保存、接续、审阅和下载行为，不证明真实模型的交付质量，也不代表四条路径均经过真实用户完整验收。

未访谈真实用户，未检验获客渠道、留存、支付意愿或各学科交付质量；不据此承诺转化率或科研水平提升。
