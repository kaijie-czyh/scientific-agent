# 研究主线闭环优化

本次只优化问题、方案、结果和判断之间的衔接，不修改实验任务生成、执行、结果回填协议或写作流水线。

## 使用入口

- 项目总览、研究问题、方案与实验、任务进度中增加“研究主线”。
- 存在多个问题或方案时明确选择；当前选择按项目保存在本机浏览器，不会替换后台任务的研究主题。
- 每条主线展示关联记录、当前缺项、建议下一步。通过按钮打开已有编辑器并预选上游关联，不自动保存或启动任务。
- 关联记录可以点击定位；引用论文仍走原文献库入口。
- 科研指导显示当前讨论参考。讨论按钮只准备输入，不自动发送或调用模型。

## 一致性与证据边界

- 仅使用当前问题和所选方案下的结果与判断，不借用其他问题的记录凑齐进度。
- 运行完成必须具备有限数值指标才能计作实测结果；失败记录允许明确写成“无法定论”。
- 记录齐全不等于创新成立、结果已独立核验或论文已完成。
- 支持对记录保存修订版本，旧记录不删除。沿用现有后端依赖规则，将下游标记为待复核；不把旧实验指标自动复制到修订结果。
- 旧流水线的论文、方法、实验和稿件保留原入口，不自动转换成新的研究记录。

## 验证

- `node tests/research_flow_state.cjs`：23 个分支、缺项、失效依赖与结果边界检查。
- `tests/research_flow_test_server.py` + `node tests/research_flow_browser.cjs`：在独立临时目录运行真实 API 和 SQLite，验证问题→方案→失败记录→无法定论的判断、跨页面定位、修订保留历史、下游待复核及多问题隔离。未运行实验、未请求模型。
- 原联邦学习验收项目只读检查：问题、方案、实测结果与“无法定论”的用户判断可完整展示，原记录不改写。
- 本次相关 Python 回归 27 项通过；此前已发现的写作结果报告失败不在本次修改范围。
