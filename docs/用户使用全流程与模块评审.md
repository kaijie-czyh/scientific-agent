# 科研发现 Agent · 用户使用全流程与模块评审

> 视角：一个用户从打开系统到拿到最终成果的完整旅程。
> 每个部分：在哪个页面 → 系统做什么 → 用户要做什么 → 预期产出 → 优化建议。

---

## 〇、全局地图

**系统定位**：文献驱动的科研发现 agent。用户给一个研究兴趣，系统跑完
「方向推荐 → 文献调研 → 思路生成 → 方法设计 → 实验规划 → 论文写作」六阶段，
全程人在回路（6 个人工确认点），最终交付论文稿 + 全流程报告。

**前端 13 个页面**（左侧导航）：

| 页面 | 路由 | 作用 |
|---|---|---|
| 项目主页 | dashboard | 状态横幅、六阶段进度条、各阶段计数、快速操作、下载区 |
| 创建项目 | create | 输入项目名/研究兴趣/领域 |
| 方向推荐 | topic-discovery | 独立子流程：把兴趣变成 3-5 个可做的选题 |
| 流程进度 | progress | 节点历史时间线、当前节点、人工节点入口 |
| 调研报告 | research-report | 交叉验证报告（缺口/共识/冲突/领域脉络） |
| 论文库 | papers | 抓取的论文列表、详情、PDF |
| 研究缺口 | gaps | 结构化 Gap 清单（类型/优先级/证据） |
| Claim 页 | claims | 核心 Claim 及其证据关联 |
| 实验 | experiments | 实验任务说明书、任务清单、结果回填 |
| 灵感笔记 | notes | 自由笔记（不参与流程） |
| 人工节点 | human | 所有等待人工确认的任务集中在这 |
| 阅读方法论 | reading-method | 静态知识页（怎么读论文） |
| 写作方法论 | writing-method | 静态知识页（怎么写论文，与五阶段对接） |

**主链路 35 个节点**：research(10) + ideation(5) + design(6) + experiment(7) + writing(7)。
另有 discovery 关系发现子流程 6 节点（独立入口，不在主链）。

---

## 一、创建项目（create 页）

- **做什么**：输入项目名、研究兴趣（如「联邦学习成员推理」）、研究领域（预设：人工智能/网络空间安全/材料/生物…，领域驱动对象-指标-方法三元组）。
- **产出**：项目实体，dashboard 出现六阶段进度条（全未开始）。
- **建议**：目前领域是下拉预设。若想让评审眼前一亮，可以在创建时加一句「自定义领域描述」自由文本，直接喂给后续 prompt——改动小、演示效果好。

## 二、方向推荐（topic-discovery 页，可选前置）

**这是独立子流程，不点「运行 Pipeline」也能单独跑。**

1. 系统按兴趣+领域规划 4-6 个细分研究方向（如联邦学习兴趣 → 成员推理/投毒/隐私/拜占庭/安全聚合），逐方向做真实论文检索取证。
2. LLM 基于检索证据（真实 DOI/arXiv 论文，不是编的）生成 3-5 条推荐主题，每条带证据论文、热度依据、创新套路分类。
3. **人工点 1（topic_select）**：从推荐里选一个（回 ok 选第一个，或输入序号/自定义主题）。
4. **产出**：RESEARCH_TOPIC 写入项目，dashboard 可见主题。

- **建议**：这步是「防止 LLM 幻觉选题」的核心卖点（每个主题都有真实论文背书），比赛必讲。目前推荐失败会走兜底模板——兜底主题质量一般，可考虑兜底时直接用方向名，不套模板。

## 三、文献调研（research 阶段，10 节点）

**启动**：dashboard 或 progress 页点「继续 Pipeline」。research 是主链第一个阶段。

| 节点 | 做什么 | 用户看到 |
|---|---|---|
| topic_refine | 润色主题为规范研究问题 | 进度条 |
| subquery_decompose | 拆解为多个检索子查询 | 进度条 |
| cp_before_confirm | 检查点（可回滚） | — |
| **topic_confirm（人工点 2）** | 确认最终研究主题 | human 页弹确认卡 |
| paper_fetch | 按 10 组查询抓真实论文（进度条实时更新，约 100 篇） | progress 页进度条 |
| paper_filter | 相关性过滤（按主题筛掉不相关论文） | 论文库数量变化 |
| paper_ingest | 入库（含 PDF 质量回填、分块） | 论文库可浏览/PDF 可读 |
| material_extraction | 抽取「对象-属性指标-方法条件」三元组知识 | — |
| cross_validate | 多源交叉验证：产出缺口(gaps)/共识(consensus)/冲突(conflicts) | 调研报告页成型 |
| research_gap | 结构化研究缺口（类型/优先级/证据/可行动性） | gaps 页成型 |

- **产出**：调研报告（research-report 页，可下载 md）；论文库；缺口/共识/冲突。
- **建议**：
  - topic_refine 与 subquery_decompose 可合并为一个节点（一次 LLM 调用同时输出两者），省一次调用与延迟；
  - paper_filter + paper_ingest 也可合并（过滤后立即入库，天然连续）；
  - topic_confirm 与方向推荐的 topic_select 连着两次人工确认，体验略冗，可考虑在方向推荐选定后默认带过 topic_confirm（或合并成一次确认）。

## 四、思路生成（ideation 阶段，5 节点）

| 节点 | 做什么 |
|---|---|
| brainstorm | 基于缺口/冲突/共识 + 论文摘要，生成 3-5 个候选思路（四维评分：新颖/可行/缺口关联/可检验性） |
| **idea_discuss（人工点 3）** | 交互式探讨：ok 全收 / reject:2 否决 / add: 补充思路 |
| idea_validate | 思路校验打分 |
| claim_draft | 从存活思路中抽取核心 Claim（贡献声明） |

- **产出**：验证过的 Idea 列表 + 核心 Claim（claims 页出现，后续全程引用）。
- **建议**：idea_validate 与 claim_draft 可合并（校验完顺手抽 Claim，一次调用）。brainstorm 已有四维评分，idea_validate 的增量价值要想清楚——如果只是再打一遍分，是裁剪候选。

## 五、方法设计（design 阶段，6 节点）

| 节点 | 做什么 |
|---|---|
| atom_decompose | 把方法拆成原子概念，建立「数学公式 ↔ 代码实现」双向映射 |
| method_formalize | 整合为 7 章节方法文档（问题定义/概述/对比/公式/伪代码/复杂度/实验建议） |
| **method_review（人工点 4）** | 审方法设计，可提修改意见 |
| claim_evidence_link | Claim 关联调研证据 |
| method_artifact | 方法文档存为版本化 Artifact |

- **产出**：方法文档（dashboard「方法文档」卡片可查看/重新生成，可下载）。
- **建议**：这是学术评委最看的部分（公式落地为伪代码），保留完整。已知坑：推理模型长输出会被 max_tokens 卡空——已修（自动升级重试），但值得在演示前多跑几次确认稳定。

## 六、实验规划（experiment 阶段，7 节点）

**定位（已按需求重塑）：系统只给任务不给代码、不代跑实验。**

| 节点 | 做什么 |
|---|---|
| experiment_config | 按方法+Claim 规划实验配置（数据集/基线/超参/任务目标/步骤/判定标准），每条=一份实验任务说明 |
| cp_before_run | 检查点 |
| **experiment_review（人工点 5）** | 审实验规划，确认后导出 |
| experiment_run | 导出任务包：experiment_plan.json + README 任务说明书到项目 experiments/ 目录（无代码） |
| anomaly_check | 检测规划异常（缺对照/缺指标） |
| claim_verify | 标注实验与 Claim 的验证关系 |
| outcome_assess | 决策口：实验未执行 → 状态 experiment_pending（等待回填）；Claim 被反驳 → experiment_failed；验证成功 → 进写作 |

- **用户操作**：到实验页查看/下载任务说明书 → 本地按说明书执行实验 → **实验页「回填实验结果」粘贴 results.json** → 状态更新为 completed → 点「继续」进写作。
- **产出**：实验任务包 + 回填后的 metrics。
- **建议（裁剪优先级最高的地方）**：
  - **anomaly_check 目前基本空转**：它检测的是「运行时异常」（loss spike/NaN），但系统已不代跑、实验都是 planned 无 metrics——**头号裁剪候选**，或改造为「规划合理性检查」并入 experiment_config；
  - claim_verify 目前价值有限（claims 经常为空，verifies_claim_ids 常全空），可并入 experiment_config 或 outcome_assess；
  - outcome_assess 是阶段门控，必须保留（含 force_writing 旁路）。

## 七、论文写作（writing 阶段，7 节点）

| 节点 | 做什么 |
|---|---|
| provenance_check | 溯源审计：检查引用证据链完整性 |
| style_learn | 从（可选上传的）范文学习写作风格 |
| outline | 骨架先行：生成论文大纲（贡献先行、可检验性） |
| cp_before_draft | 检查点 |
| section_draft | 按大纲逐节起草（证据先于文字） |
| review | 自审（贡献兑现审计） |
| **revise（人工点 6）** | 用户确认修改 |

- **产出**：论文稿 paper_draft Artifact（可下载）。
- **建议**：style_learn 在用户没上传范文时行为要检查（空素材应静默跳过）；其余保留。

## 八、全部完成（completed）

**预期最终交付物**（dashboard 下载区，9 类）：
全流程报告（8 部分合订）、调研报告、思路汇总、方法文档、实验任务书、实验结果、Claim 汇总、发现报告、论文稿。

典型完成状态一路径：6 个人工点全部 ok → experiment_pending 回填 → 写作 → completed。

---

## 九、独立功能（不在主链路）

1. **关系发现 discovery（MCTS + LLM 引导搜索，6 节点）**：独立子流程，做跨论文关系/新颖发现，产出发现报告。比赛演示的差异化亮点，但不在主链。
2. **灵感笔记 notes**：自由记录，与流程无关。
3. **两个方法论知识页**：静态内容，零维护成本。

- **建议**：discovery 保留（演示亮点）但别再投入；notes 保留（成本≈0）；方法论页保留（给评委讲「我们不止是工具，还有方法论沉淀」）。

## 十、模块评审速览（按裁剪优先级）

| 优先级 | 模块 | 理由 | 建议 |
|---|---|---|---|
| 🔴 高 | anomaly_check | 不代跑实验后基本空转 | 裁掉或改造并入 experiment_config |
| 🔴 高 | claim_verify | claims 常为空，链路没打通 | 并入 experiment_config / outcome_assess |
| 🟡 中 | idea_validate | 与 brainstorm 四维评分重叠 | 与 claim_draft 合并 |
| 🟡 中 | topic_refine + subquery_decompose | 两步可一步 | 合并为一个节点 |
| 🟡 中 | paper_filter + paper_ingest | 天然连续 | 合并 |
| 🟡 中 | topic_select 与 topic_confirm | 连续两次人工确认 | 合并为一次 |
| 🟢 低 | discovery / notes / 方法论页 | 成本低、有演示价值 | 保留 |
| ⛔ 别动 | outcome_assess / provenance_check / 全部人工门控 | 阶段门控与可信度核心 | 保留 |

> 合并节点的额外收益：每次合并省一次 LLM 调用与一个检查点，全程人工点击从 6 次降到 5 次以内，演示节奏更快。
