# 项目管理优化

项目总览和任务进度沿用原导航，增加项目管理卡片，不修改实验执行和写作流水线。

## 主要内容

- 查看、编辑并保存研究目标、已有基础、可用资源和时间安排，复用原有项目约束接口和 SQLite 持久化。
- 区分后台任务状态与科研推进状态。任务结束不表示研究完成，实验失败不等于设想被反驳。
- 显示现有文献与研究记录，原流程实验单独展示，不相加冒充独立实验数量。
- 根据当前研究主线提示缺少的材料、待复核记录和下一步工作。
- 下一步建议提供去处理、讨论调整、暂不提醒。处理只打开现有入口；讨论不自动发送；暂不提醒仅是按项目保存在本机的显示偏好，不修改研究进展。

## 保存与保护

- 保存实际变化前，已有研究记录的项目需要明确确认。沿用原规则：变更约束后，现有非笔记研究记录标为待复核，不删除原内容，不自动重跑实验。
- 没有变化时不发送保存请求，不增加版本，不触发复核。
- 未保存输入按项目留在当前浏览器会话的草稿中，切页和轮询不会覆盖。
- 并发版本冲突不自动重试覆盖；提示核对最新记录，并保留输入。
- 正式保存的约束进入项目数据；草稿和隐藏建议不是云端同步的项目任务系统。

## 验证

- `node tests/project_management_state.cjs`：12 项状态、统计及建议边界检查。
- 独立临时服务上的 `node tests/project_management_browser.cjs`：真实 API 和 SQLite 保存、无变化不增加版本、草稿切页与轮询保护、版本冲突、复核确认、隐藏建议不修改项目、科研指导携带约束。
- 研究主线、导航计数、原实验回填界面与回复头像执行回归。测试不请求模型、不运行实验、不改用户项目。
