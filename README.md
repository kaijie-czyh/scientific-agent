# Scientific Agent · 科研协作工作台

**让 AI 参与科研过程，让研究者掌握研究方向。**

Scientific Agent 是一个面向计算机与 AI 研究的智能科研辅助系统。它将选题探索、文献阅读、研究问题、方法设计、结果整理与写作放在同一个工作台中，让你与 AI 围绕真实材料持续协作，而不是每完成一个阶段，就换一个工具、重新解释一遍项目。

你可以从一个宽泛的兴趣开始，也可以带着已有论文、想法或实验记录继续。系统帮助整理依据、讨论方案和明确下一步；研究者负责选择问题、审核方法、执行验证并确认结论。

## 为什么需要这样的工作台

科研并不只是“找论文”和“生成文字”。更困难的是把过程串起来：读到的工作与自己的问题有什么关系？提出的改进是否只是已有方法的变体？有限的时间和设备能够验证什么？结果没有达到预期，还能说明什么？

Scientific Agent 希望把这些讨论留在研究过程中。文献、设想、方案与结果不再只是聊天记录中的零散片段，而是可以保存、关联、修订和回看的项目材料。AI 也不只在最后帮你润色，而是在每个阶段协助你理解材料、检查思路与组织工作。

目前适合课程研究、毕业设计、论文复现、方法对比和小型科研项目，重点面向学生、科研入门者与需要组织研究过程的开发者。

## 用户与 AI 如何共同推进研究

系统采用“**AI 提供辅助 → 用户核对与选择 → 保存研究记录 → 根据新证据继续修订**”的协作方式。用户不必接受 AI 的所有建议，也不需要每次从头开始。

| 研究阶段 | AI 与系统提供的辅助 | 用户参与的关键工作 | 留下的研究材料 |
| --- | --- | --- | --- |
| 确定范围 | 结合兴趣与文献探索方向，讨论时间、设备和已有基础是否匹配 | 补充约束，选择或修改方向 | 项目目标、候选方向与推荐依据 |
| 理解研究现状 | 检索和整理相关工作，辅助阅读方法、结果与局限 | 筛选论文、核查原文、补充重要研究 | 文献库、阅读记录与研究缺口 |
| 明确研究问题 | 对照已有工作，讨论差异，将宽泛想法收敛为可检验的问题 | 判断研究价值，确认本次推进的问题 | 关联文献的研究问题与灵感笔记 |
| 制定方法与方案 | 拆解数据条件、对照、变量、指标和验证步骤 | 审核可行性、公平性与资源需求 | 方法方案、实验计划与任务说明 |
| 验证与分析 | 接收实际结果，辅助讨论支持、反驳或无法定论的情况 | 在自己的环境执行实验，回填结果并作出判断 | 结果记录、依据与适用条件 |
| 整理成果 | 根据已有材料组织提纲、稿件和修改建议 | 核对引用、数字、论证与最终表述 | 写作骨架、稿件与可导出的文档 |

```text
研究兴趣 → 文献与研究现状 → 研究问题 → 方法与验证方案
                                         ↓
成果整理与写作 ← 结果分析与研究判断 ← 外部执行与结果回填
```

这条路径可以暂停、回退和修订。新论文可能改变问题的范围，实验也可能推翻最初设想；系统保留这些变化，而不是要求每个项目都沿着预设路线得到“成功结论”。

## 科研指导不只是一个聊天框

右侧科研指导结合当前页面、项目目标、选中的论文与研究记录参与讨论。你可以在阅读时问“这篇方法与我的问题有什么关系”，在设计时问“这些对照是否公平”，也可以在写作时问“哪些论断还缺少证据”。

指导逻辑结合论文阅读、创新思路和写作组织的方法：阅读时关注研究动机、方法、结果与局限；讨论创新时对照最接近的工作，区分已知差异和待验证设想；写作时根据证据组织论证，而不是先写出结论再补数字。这些方法帮助组织讨论，不等于系统已经替你证明新颖性。

**对话建议与正式研究记录分开。** 合适的建议由你明确采纳为笔记、问题、方案或写作骨架；临时想法可以先放入灵感笔记。AI 不会因为说出一个结论，就将它当成已验证结果。

## 项目的优势与侧重点

### 1. 围绕项目协作，而不是停留在单次回答

项目总览、文献、研究问题、方案与写作围绕同一项研究组织。除了生成内容，系统还帮助你查看已有材料、待处理事项和下一步，让讨论能够转化为实际推进的工作。

### 2. 从文献衔接到验证，而不是调研结束就失去联系

文献中的依据可以关联到研究问题，问题再衔接方法、结果与判断。已有思路和方法材料可以经过确认后继续使用，不必为了进入下一阶段重新生成一套内容。

### 3. 适应科研的长周期，而不是要求一次在线完成

实验任务保存后，你可以离开网页，在自己的电脑或服务器执行。之后回到原项目继续回填、讨论和整理。系统保留项目材料与修订历史；服务重启后，正在执行的请求仍需检查状态，不承诺所有外部调用无缝续接。

### 4. 区分设想、结果与判断，而不是把内容齐全当作研究成立

计划完成不等于实验完成，程序运行成功也不等于设想成立。系统分别记录实际结果与研究判断，允许保留运行失败、负面结果和无法定论。修改问题或方案时，还会提示复核依赖旧内容的记录，减少沿用过时依据的风险。

与侧重即时回答的聊天工具、侧重文献获取与阅读的工具相比，本项目更关注**阅读之后怎样形成问题、怎样安排验证，以及怎样根据证据继续研究**。它可以与专业文献管理器、实验脚本和写作工具配合使用，不以替代所有工具为目标；以上是产品定位，不是对其他系统的性能排名。

## 一个例子：把联邦学习兴趣变成可以推进的研究

假设你希望研究联邦学习中的数据异质性，但还没有明确选题，设备与时间也有限。

**先讨论范围。** 你在项目中说明已有基础和资源，系统检索相关文献，帮助梳理不同方法关注的问题。你可以追问推荐方向的依据，也可以否定不符合条件的方向。

**再确定问题与方案。** 根据阅读，将兴趣收敛为“指定公开数据与固定训练预算下，两种聚合方法对数据分布变化的敏感程度是否不同”。系统辅助整理划分方式、对照、重复次数与指标，你审核后保存方案。

**实验在外部完成。** 你导出任务说明，在自己的环境中执行，几天后回到同一项目登记指标与失败情况。科研指导协助讨论差异是否足够支持判断，而不是自动将数值更高的方法写成普遍更优。

**最后整理成果。** 如果优势只出现在部分条件下，就保留条件与局限；证据不足时，也可以记录无法定论。写作围绕实际材料展开，缺少的结果继续留待验证。

这个过程中，AI 提供信息整理和思考辅助，你提供目标、选择与真实证据。最终留下的是能够继续修订的研究过程，而不只是一份自动生成的报告。

*此例说明使用方式，不是实测成果，也不代表该问题已被证明具有创新性。完整操作见[使用指南](docs/user-guide.md)。*

## 当前支持的研究范围

- **AI 与机器学习**：论文复现、方法对比、模型评测、联邦学习与检索增强生成等。
- **软件工程与计算机系统**：软件测试、程序分析、系统可靠性与性能评估。
- **计算机安全与隐私**：公开数据、模拟环境或明确授权范围内的安全研究与评测。

当前不提供医学、临床、湿实验、实物设备操作或真人访谈的完整研究指导。实验以用户外部执行、结果回填为主，不提供面向公众的无人值守自动实验。

## 技术如何支撑协作

Scientific Agent 采用 **Agent Harness** 思路，将模型、检索工具、分阶段任务、人工确认和过程保存组织起来。Harness 不是另一个基础模型，而是让模型能够在可查看、可确认、可修订的研究流程中工作的支撑层。

后端使用 Python、FastAPI 与 Pydantic；通过任务配置路由模型；使用 SQLite 和本地目录保存项目、关联记录与产物；前端采用原生 HTML、CSS 和 JavaScript。研究记录保留来源与版本，关键操作由用户确认，而不是让模型直接替用户认定实验结果或研究结论。
