# Scientific Agent · 科研 Agent 系统

一个面向科研学习与项目实践的 AI 辅助研究工作台，围绕 **选题、文献、问题、方法、实验和写作** 组织整个研究过程。

系统不只是一个“输入主题、生成论文”的聊天窗口：它将研究任务拆成可以查看进度、人工确认和保存结果的步骤，让论文证据、研究设想、实验记录与最终稿件之间建立联系。

> 当前为持续迭代中的开发版本。首版聚焦计算机与 AI 研究辅助，不再以 GOAI 赛题或材料科学作为产品定位。历史领域的项目与材料保留，但不再开放非计算机领域的新推荐与自动指导。系统尚未完成面向公众上线的全部安全加固与端到端验收。

## 项目解决什么问题

科研过程中，选题建议、论文阅读、方法讨论、实验记录和稿件经常分散在不同工具中。这个项目尝试把它们放到同一个工作台：

- 从宽泛的兴趣出发，结合检索到的论文寻找更具体的研究方向，而不是只返回通用题目。
- 将文献中的已知结论、模型提出的设想和用户实验得到的结果分开保存。
- 在检索方向、研究思路、方法方案等关键位置保留人工确认，允许用户修改再继续。
- 通过右侧科研指导对话讨论当前阶段的问题，将合适的建议采纳为研究记录。
- 保留灵感笔记、任务进度、实验结果及写作产物，便于回看和整理成果。

适合计算机相关的课程研究、毕业设计、复现与评测、小型科研项目的过程管理。当前新项目只开放三个方向：**AI 与机器学习、软件工程与计算机系统、计算机安全与隐私**。领域选择影响检索和分析口径，不代表系统已经独立验证方案或科研结论。

暂不提供医学、临床、药物、湿实验、实物设备操作指导，以及真人访谈或人体实验的完整指导与伦理审定。安全研究仅限公开数据、模拟环境或明确授权的测试。系统不代跑实验，不保证创新成立。

新建及自动生成接口会校验领域标识；空领域为兼容旧客户端按 `computer_science` 处理。这是产品范围限制，不是对任意主题进行可靠高风险语义识别的安全防线。历史非计算机项目仍可查看文献、对话、笔记和导出记录，不会被删除或自动改成计算机项目。旧领域画像和 CLI 底层接口仅保留兼容，不属于首版公开能力承诺。

## 完整使用流程

```text
新建项目：填写研究兴趣、领域与目标
    ↓
选题探索：检索论文，整理方向、推荐理由与证据
    ↓
文献调研：确认检索问题，收集、筛选、导入和阅读论文
    ↓
研究现状与问题：整理已有方法、争议和研究缺口
    ↓
思路探讨：提出候选方案，用户修改或选择
    ↓
方法设计：确定数据、对照组、变量、指标与实施步骤
    ↓
实验任务：审核并导出实验计划与任务说明
    ↓
用户在自己的环境执行实验 → 回填真实指标和结果说明
    ↓
结果分析：判断设想得到支持、被反驳，还是证据不足
    ↓
成果写作：检查材料来源，生成大纲和草稿，审阅与人工确认
    ↓
导出文档，或根据问题回到前面的阶段继续修改
```

这不是一次点击后无人参与的直线流程。遇到待确认事项、外部服务失败、材料不足或实验尚未完成时，系统会等待用户处理，不能把失败阶段当成已完成。

| 阶段 | 系统负责什么 | 用户负责什么 | 主要产出 |
| --- | --- | --- | --- |
| 选题探索 | 检索相关论文，结合领域与证据组织候选方向 | 说明兴趣、时间和资源限制，选择或自定义主题 | 推荐方向、依据、候选问题 |
| 文献调研 | 分解检索问题，调用文献源，筛选、入库和整理材料 | 确认检索范围，补充重要文献，核查全文 | 项目文献库、摘要和来源记录 |
| 研究问题 | 整理研究现状、冲突与缺口，提出候选思路 | 判断问题是否值得研究，修订范围和假设 | 研究问题、候选思路、待验证主张 |
| 方法设计 | 拆解方案，整理方法、对照和评价要求 | 审核数据可得性、资源预算及实施条件 | 方法文档、实验设计 |
| 方案与实验 | 导出任务包，接收指标，建立结果与主张的关系 | 实际运行实验，回填结果并保留原始记录 | 实验计划、指标、结果判断 |
| 成果写作 | 基于已有材料组织大纲、正文和审阅建议 | 核对引用、方法和数字，确认最终表述 | 草稿、结果报告及可导出的成果 |

### 用“联邦学习中的投毒防御”举例

1. 输入研究兴趣，同时说明“本学期完成、只有 CPU、希望做可复现的小规模实验”。
2. 根据实际检索结果区分标签翻转、模型投毒、鲁棒聚合等问题，不把所有方向都写成同一套推荐理由。
3. 阅读并补充与选定问题相关的论文，明确威胁模型、数据条件和对照方法。
4. 将问题收敛为可执行的对比，例如特定投毒条件下两种聚合方法的表现。
5. 审核客户端数量、数据划分、恶意比例、随机种子和评价指标，再导出任务。
6. 在本地或服务器运行自己的实验，将实测指标与说明回填系统。
7. 仅在证据覆盖的范围内撰写结果；不能将合成数据上的小规模观察写成真实场景下的普遍结论。

这里展示的是使用方式，不是系统预设的唯一选题，也不代表该例已证明创新性。

## Agent Harness 与技术实现

这里的 Harness 指围绕模型构建的任务执行与约束层，并不是另一个基础模型。

| 能力 | 当前实现 |
| --- | --- |
| 分阶段编排 | 将调研、思路、方法、实验、写作拆成节点与子图，由运行时调度 |
| 人工确认 | 关键节点暂停，接收用户反馈后继续或调整 |
| 模型路由 | 按任务类型读取 YAML 配置，选择 provider、模型和生成参数 |
| 结构化输出 | 用 Pydantic 定义数据格式，校验模型输出与结果回填 |
| 检索与知识管理 | 文献检索、分块与检索辅助，SQLite 保存实体及关联，ChromaDB 提供可选向量能力 |
| 过程恢复 | 保存阶段状态、执行上下文和检查点，支持恢复入口；不是所有外部请求都能自动续接 |
| 证据与产物管理 | 关联论文、待验证主张、实验和文档，保存产物版本及来源信息 |

技术栈：

- 后端：Python 3.10+、FastAPI、Uvicorn、Pydantic。
- 存储：SQLAlchemy、SQLite，按项目保存数据；ChromaDB 为可选向量检索组件。
- 前端：原生 HTML / CSS / JavaScript，不需要前端打包构建。
- 模型适配：OpenAI 兼容协议适配层，以及 Anthropic 等 provider 接口。
- 文献工具：Sciverse、arXiv、Semantic Scholar，以及 Crossref、OpenAlex 等检索或元数据辅助工具；实际调用依节点与配置而定。
- 文档：Markdown、python-docx、fpdf2。

已有输入校验、引用范围约束和产物溯源机制，不代表已经具备完善的提示注入防护、安全沙箱或多租户安全隔离。

## 快速开始

### 1. 获取代码并安装依赖

建议先在本地单用户环境体验，准备 Python 3.10 或以上版本。

```bash
git clone https://github.com/weimeng09280929/scientific-agent.git
cd scientific-agent
python -m venv venv
```

Windows PowerShell：

```powershell
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Linux / macOS：

```bash
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
```

如果 PowerShell 不允许激活脚本，可直接使用 `venv\Scripts\python.exe` 代替命令中的 `python`，无需修改系统执行策略。

需要本地 PDF 文本提取时，可补装：

```bash
python -m pip install pypdf
```

扫描版 PDF 可能需要额外 OCR；存在 PDF 文件不等于系统已取得可阅读正文。

### 2. 配置真实模型调用

编辑本地 `.env`：

```dotenv
SRA_DRY_RUN=false
DEEPSEEK_API_KEY=填写你自己的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
```

**密钥、接口地址、模型名称必须属于同一套可用服务。** 如果使用兼容网关，将地址改为该服务给出的地址，并确认模型确实可调用。

当前 `config/tasks.yaml` 中主流程任务路由使用 `deepseek` provider，模型标识为 `deepseek-v4.1-flash`。这是仓库当前的配置值，不是对该模型在任意服务商处可用的保证；请以你实际账号支持的模型为准。

只填入其他厂商的 key 不会自动切换所有任务，还需要修改任务路由，详见下一节。

### 3. 启动网页

在仓库根目录运行：

```bash
python -m uvicorn web.api:app --host 127.0.0.1 --port 8001 --workers 1
```

访问：

- 工作台：[http://127.0.0.1:8001/workspace](http://127.0.0.1:8001/workspace)
- API 文档：[http://127.0.0.1:8001/docs](http://127.0.0.1:8001/docs)

如需换端口，先设置 `SRA_WEB_PORT`，再把启动命令中的 `--port` 改为同一数值，因为启动检查也会读取该变量。

请使用单 worker。任务线程和人工等待桥目前在单个服务进程内，多 worker 会造成任务状态不一致。

### 4. 开始一个研究项目

在“新建与管理”中填写兴趣或研究主题，进入选题探索或已有主题的研究流程。建议第一次选择范围较小、文献较充分、实验资源可控的问题。

运行过程中查看“任务进度”和“待确认事项”。实验阶段需要用户实际执行任务并回填结果，不应跳过这一步直接宣称研究已完成。

停止本地服务时，在启动终端按 `Ctrl+C`。请勿删除 `projects/`，其中保存着本机的科研项目。

## 模型与检索配置

### 任务与模型分开配置

- `.env`：保存私有凭据、服务地址和运行开关，不提交 Git。
- `config/tasks.yaml`：保存各任务使用的 provider、model、temperature、max_tokens 等参数。
- `SRA_TASKS_CONFIG_PATH`：可指定另一份任务配置文件。
- 已设置的系统环境变量优先于 `.env`；更改后需重启服务。

例如，单个任务的路由形式为：

```yaml
tasks:
  research_subquery_decompose:
    provider: deepseek
    model: 你实际开通的模型标识
    temperature: 0.2
```

这是配置结构示例，不是可以覆盖整个文件的完整配置。切换主模型时，应检查所有需要使用新模型的任务，包括选题、科研指导和写作。

### 可选配置

| 配置 | 用途与注意事项 |
| --- | --- |
| `SCIVERSE_API_TOKEN` | 启用需要授权的 Sciverse 检索；不配置时仍可尝试其他文献源 |
| `OPENAI_API_KEY` | 当前嵌入路由使用的凭据；聊天模型 key 不一定支持嵌入 |
| `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` | MiniMax 或配置到该 provider 的兼容服务，需同步修改任务路由 |
| `SILICONFLOW_API_KEY` / `SILICONFLOW_BASE_URL` | 硅基流动兼容接口，需同步修改任务路由 |
| `SPARK_API_KEY` / `SPARK_BASE_URL` | 星火接口，需同步修改任务路由 |
| `MIMO_API_KEY` / `MIMO_BASE_URL` | MiMo 接口，需同步修改任务路由 |
| `ANTHROPIC_API_KEY` | Anthropic provider，需同步修改任务路由 |
| `LOCAL_LLM_BASE_URL` | 本地兼容服务；仅配置地址不会自动将敏感任务改为本地执行 |
| `MINERU_API_KEY` / `MINERU_BASE_URL` | 可选的远程 PDF 解析；使用前评估文献上传权限和隐私 |
| `MATERIALS_PROJECT_API_KEY` | 仅供材料相关扩展使用，通用科研主流程不要求配置 |

关键词检索与向量检索不是同一种能力。没有可用的嵌入服务时，不应把关键词回退说成已经完成语义向量检索。

### 真实模式与架构演示模式

- `SRA_DRY_RUN=false`：使用实际配置的模型服务；调用会消耗该服务的额度。检索还取决于外部网络、数据源及限流情况。
- `SRA_DRY_RUN=true`：架构演示模式，部分节点使用占位数据，不执行真实模型调用。**不能用它验证模型可用性、文献真实性或科研结论。**

检索没有结果时应展示失败或材料不足，不能将演示数据、通用占位题目或编造的增长率冒充真实推荐。

## 实验与写作的边界

### 系统目前如何处理实验

默认实验子图以“规划与交付任务”为主：

1. 根据审核过的方法生成实验配置。
2. 经用户确认后导出 `experiment_plan.json` 和任务说明。
3. 用户用自己的脚本、设备或服务器执行。
4. 在页面回填实验状态、真实指标与说明。
5. 系统分析结果并关联需要验证的主张。

仓库保留了代码生成、代码运行等工具，但这些工具的存在不意味着当前网页主流程已经具备可直接对公众开放的自动实验执行能力，更不意味着具备安全隔离。

回填通过格式校验，也不等于系统已经独立验证原始实验。研究者仍需保留代码、数据来源、运行日志、随机种子和失败记录。

### 如何理解研究结论

代码中的 Claim 指“需要证据检验的研究主张”，不是模型说出的一句结论就自动成立。

- 文献支持：说明已有研究提供了相关证据。
- 实验完成：说明取得了实际结果。
- 主张得到支持：需要结果与研究条件确实匹配。
- 证据不足、负面结果或无法判断：应如实保留，不能改写成创新已经被证明。

写作阶段基于已有材料进行来源检查、大纲组织、章节生成、审阅与人工确认。对于证据不足的实验，结果整理报告与正式论文结论应区分，不能为了生成稿件补造证据。

文档可按页面支持情况导出 Markdown、Word 或 PDF。导出不等于投稿就绪；引用、数字、图表和中文字体仍需核查。当前 PDF 字体处理偏向 Windows，Linux 服务器的中文 PDF 导出需要另外适配。

## 数据保存与项目结构

每个科研项目拥有独立目录，通常包括知识库、检查点、论文文件和产物：

```text
scientific-agent/
├── config/tasks.yaml        # 任务与模型路由
├── core/
│   ├── orchestration/       # 节点、图与执行上下文
│   ├── state/               # 生命周期与快照
│   ├── llm/                 # 模型 provider 与结构化调用
│   ├── knowledge/           # 文献、研究对象、主张与关联存储
│   ├── artifacts/           # 产物版本与来源管理
│   ├── workspace/           # 研究记录与科研指导
│   └── tools/               # 检索、解析与领域辅助工具
├── stages/
│   ├── topic_discovery/     # 选题探索
│   ├── research/            # 文献调研
│   ├── ideation/            # 思路讨论
│   ├── design/              # 方法设计
│   ├── experiment/          # 实验规划、交付与结果判断
│   ├── writing/             # 写作与审阅
│   └── discovery/           # 可选关系发现扩展，不是通用主流程必经阶段
├── runtime/                 # 流程调度与恢复
├── web/                     # FastAPI 接口和网页
├── tests/                   # 单元、回归及浏览器测试
├── tools/                   # 检查与验收辅助脚本
├── docs/                    # 架构、迭代说明及历史文档
├── projects/                # 本机科研项目数据，不提交 Git
└── .env                     # 本机密钥和运行配置，不提交 Git
```

## 服务器部署与上线要求

项目目标是成为可供真实用户使用的科研辅助产品，但当前开发版不应直接当作已完成安全验收的公网服务。

部署到受控服务器进行小范围验证时，至少需要：

1. **单进程运行与持久化存储**：使用单 worker，保留并备份 `projects/`；容器更新不能覆盖科研数据。
2. **凭据管理**：通过服务器环境或私有配置注入密钥，不将 `.env` 打包或上传；日志不能包含密钥。
3. **HTTPS 与访问控制**：配置反向代理、登录鉴权及项目归属校验。当前没有完善的多用户认证与租户隔离。
4. **资源与调用保护**：补充限流、费用预算、任务超时、并发控制与滥用防护。
5. **文件与执行安全**：审核上传文件、外部 URL 下载、目录访问和代码执行边界，不能直接开放任意代码执行。
6. **运营与恢复能力**：监控异常、备份恢复、错误告警，并验证服务重启和任务恢复。
7. **最终验收**：用真实模型与真实用户任务检查检索、指导、结果回填、稿件和导出，明确失败与人工介入路径。

目前任务线程与状态桥没有独立任务队列，SQLite 也不等于高并发多用户后端。不要直接增加 Uvicorn worker 数量来当作扩容方案。

仓库保留 Docker 和早期平台部署文件，但尚不能据此宣称容器部署、中文 PDF、多用户安全和公网运维均已验收。当前版本也不因存在旧配置而自动具备支付或商业结算能力。

## 常见问题

**为什么检索失败或很慢？**

检查模型配置、论文源网络、授权、限流和关键词范围。查看失败节点与日志，不要通过填入假论文来绕过失败。

**有论文记录，为什么没有 PDF？**

论文元数据、摘要和全文是不同内容。部分论文受版权或访问权限限制；系统只能尝试下载可访问或用户有权提供的文件，不保证所有论文都能下载。

**有稿件，为什么“成果写作”数字还是 0？**

稿件产物与工作台写作记录目前不是同一种统计对象，部分显示还存在一致性问题。请结合具体产物和任务状态检查；这个数字不代表论文质量或全部流程已经完成。

**系统能直接自动写出可投稿的论文吗？**

不能作出这种保证。系统辅助整理材料和起草文本，真实研究、实验真实性、引用核验和最终学术责任仍由研究者承担。

**为什么源码里还有材料、GOAI 或早期部署内容？**

这些是早期实现和历史文档。当前首版主线聚焦计算机与 AI 研究；材料相关代码仅保留历史兼容，不作为公开支持能力，也不是参赛资格要求。
