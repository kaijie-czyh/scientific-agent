# Scientific Agent · 科研 Agent 工作台

**从一个研究兴趣出发，把文献、问题、方案、结果与写作连接起来。**

Scientific Agent 是一个面向计算机与 AI 研究的智能科研辅助工作台。它将文献检索、选题探索、科研指导、实验规划和成果整理放在同一个项目中，帮助你逐步明确研究问题，制定验证方案，并保留每一步的依据与进展。

你可以与 AI 讨论，也可以随时暂停、修改和继续。系统负责辅助研究与组织过程，关键选择和研究判断始终由你掌握。

## 为什么使用 Scientific Agent

研究往往不是缺少一个答案，而是需要把零散的论文、想法、实验和结论逐步串起来。

Scientific Agent 围绕一条持续保存的研究主线组织工作：**这个问题从哪里来，准备用什么方法验证，得到了什么结果，最后能说明什么。** 你不需要在每次讨论时重新交代全部背景，也不必将已有内容在不同阶段反复录入。

- **有依据地找方向**：结合检索到的文献讨论研究机会，查看推荐理由、相关工作和待核实的问题。
- **围绕项目持续讨论**：科研指导结合当前项目和选中的内容，帮助你理解论文、收窄问题、检查方案。
- **按自己的节奏推进**：关键步骤由你确认，离开页面或暂停研究后，可以回到已有项目继续。
- **让结果与结论对应**：方案、实际结果和研究判断分别记录，保留来源、关联和修订历史。

## 核心功能

| 功能 | 你可以做什么 |
| --- | --- |
| 选题探索 | 输入研究兴趣，结合相关文献查看候选方向、推荐理由与创新切入点，逐步收敛研究范围 |
| 文献检索与阅读 | 检索、筛选和导入论文，查看摘要与来源，尝试下载可访问的全文，并围绕论文展开讨论 |
| 研究现状梳理 | 整理已有方法、共识、争议和研究缺口，为研究问题寻找具体依据 |
| 科研指导对话 | 在右侧对话框讨论当前任务，将需要保留的建议明确采纳为笔记、问题、方案或写作骨架 |
| 方法与实验规划 | 组织数据条件、对照方法、评价指标和验证步骤，查看与导出实验任务说明 |
| 结果回填与判断 | 登记外部执行后的实际结果，记录支持、反驳或无法定论的判断，并关联到对应方案 |
| 成果整理与写作 | 保存写作骨架，查看已有稿件和修改意见，按页面提供的入口导出研究记录与文档 |
| 项目管理与恢复 | 查看当前主线、已有内容和下一步，切换或继续项目，按需搜索和批量管理项目 |

## 研究流程

```text
研究兴趣与项目目标
        ↓
文献检索与研究现状
        ↓
明确研究问题
        ↓
制定方法与验证方案
        ↓
外部执行 → 回填实际结果 → 记录研究判断
        ↓
整理成果与写作
```

这条路径允许反复修订：阅读发现新的限制，可以回到问题与方案；结果没有支持原设想，也可以保留负面结果与局限，继续讨论下一步。

已有思路、方法文档和实验任务可以直接关联到当前主线。确认关联后，原始内容与来源仍然保留，不需要重新复制一份才能继续研究。

## 一个贯穿全流程的案例：联邦学习研究

假设你想研究联邦学习，但目前只有一个宽泛的兴趣：

> 我想了解数据分布不一致时，联邦学习方法的表现；设备有限，希望先做一个可以完成的小项目。

下面展示的是**使用流程示例，不是已完成的研究或实测结果**。候选方向需要以当次检索到的文献为依据，系统不保证固定推荐某个题目。

1. **先明确条件，再找方向。** 在项目中记录时间、设备与已有基础；结合检索到的论文，在“研究现状”梳理不同方法处理什么问题、采用什么条件。科研指导帮助你讨论选题的可行性，而不是直接把“联邦学习”扩写成一篇报告。
2. **把兴趣缩成可以验证的问题。** 例如，经过阅读后，将问题收敛为“在指定公开数据和固定训练预算下，两种聚合方法对数据异质性的敏感程度是否不同”。保存问题及其关联文献，同时把尚未确认的想法留在灵感笔记中。
3. **把问题变成具体方案。** 在“方案与实验”记录数据划分、对照方法、训练预算、评价指标、重复次数和资源条件。通过科研指导检查是否只改变了要比较的因素，避免因为训练设置不同而误判方法优劣。
4. **离开系统做实验，回来接着研究。** 保存任务后，在自己的电脑或服务器执行。几天后重新打开同一项目，将实际指标、失败情况和结果说明回填到原方案，不必一直开着网页，也不必新建项目从头开始。
5. **让结论对应实际证据。** 如果一种方法只在部分划分下有优势，就记录适用条件与局限；如果差异不明确，就保留“证据不足”的判断，而不是生成一个看似成功的结论。若修改了问题或方案，再复核依赖旧版本的记录。
6. **将过程整理为成果。** 在“成果写作”组织研究背景、问题、方法、结果与局限，将已经核实的内容纳入稿件。最终保留下来的不只是一段 AI 回答，而是可以继续修订的研究记录和写作材料。

**这个案例体现的价值：把“读过哪些论文、为什么这样做、实际得到什么、能够说明什么”放回同一个项目中。** 系统帮助管理研究的衔接与证据，不承诺自动发现创新点或自动完成实验。

## 与其他科研工具有什么不同

Scientific Agent 的定位是**围绕研究项目持续推进的协作工作台**，而不是单独的论文问答器，也不是一键生成论文的工具。

下表按工具的使用重心说明定位差异，不是对某个产品的功能穷举或性能排名；其他工具也可能覆盖其中部分能力。

| 工具类型 | 主要使用重心 | Scientific Agent 更强调什么 |
| --- | --- | --- |
| 通用 AI 对话工具 | 围绕问题进行讨论与内容生成 | 将采纳后的讨论关联到项目、问题和方案，明确当前进度与下一步 |
| 论文检索与问答工具 | 找论文、读论文、回答文献问题 | 将阅读得到的依据继续衔接到研究问题、验证方案和成果整理 |
| 文献管理与笔记工具 | 保存文献、组织引用和阅读记录 | 在保存资料之外，组织问题—方案—结果—判断之间的关系；不替代专业参考文献管理器 |
| 自动研究或实验 Agent | 侧重将更多研究步骤交给 Agent 执行 | 当前以人工确认、外部实验和结果回填为主，明确区分规划、执行与已验证结论 |

### 我们希望做好的四件事

- **少一点阶段割裂。** 研究现状不是单独生成后就结束的报告，而是后续问题与方案的依据；已有方法和任务可以关联到主线，减少重复整理。
- **适应真实科研的长周期。** 研究可以暂停、回退和修改，实验不必在一个在线会话内完成。回来后仍能找到原问题、任务与记录。
- **把“建议”与“证据”分开。** AI 的设想、计划中的实验、实际结果和研究判断分别保存，既容纳失败与负面结果，也避免把预期效果写成实测结论。
- **让修改的影响可见。** 问题或方法变化后，提示复核相关下游内容，帮助研究者避免继续引用已经过时的方案与结果。

这些是产品的设计重点，不代表已经证明比其他系统更准确或更高效。检索质量受数据源可用性影响，建议质量依赖模型与输入材料，研究者仍需核对论文与判断；当前也不提供无人值守的实验执行能力。

## 开始使用

### 1. 创建项目，说明你想研究什么

进入“新建与管理”，选择研究领域并填写兴趣或主题。如果还没有确定选题，可以先进入“选题探索”；如果已经有明确问题，也可以围绕现有主题开展研究。

在项目总览补充目标、已有基础、时间安排和可用资源，让后续讨论更贴近你的实际条件。

### 2. 阅读文献，确认一个具体问题

在“文献库”和“研究现状”查看相关工作，结合科研指导，区分已经知道的结论、仍有争议的问题和需要进一步验证的设想。

将合适的候选思路关联为研究问题，或手动保存自己的问题。多个问题可以保留在同一项目中，但需要明确当前推进哪一个，避免混用不同问题的方案和结果。

### 3. 核对方案，安排验证任务

进入“方案与实验”，关联已有方法或制定研究方案。确认数据是否可得、对照是否公平、指标是否合适，以及时间和设备能否支撑实施。

系统提供规划与记录，**不代替你执行实验**。任务保存后，可以离开工作台，在自己的电脑或服务器上完成验证，再回来继续。

### 4. 回填结果，形成有依据的判断

将实际指标、运行情况与结果说明关联到对应方案。对于已经关联的实验任务，结果登记会同步到对应任务记录；也可以使用任务提供的 JSON 入口批量回填。

程序运行失败、结果不支持设想和证据暂时不足，是不同情况。系统支持分别记录，不要求每次研究都得到正向结论。

### 5. 整理成果，保留证据与局限

在“成果写作”组织研究问题、方法、结果和局限，保存提纲，查看已有稿件，并导出需要的记录或文档。

背景、方法和写作骨架可以提前整理；结果与结论应以实际证据为依据。预期效果和演示数据不能作为实测结果使用。

## 随时讨论，也能接着上次继续

### 右侧科研指导

科研指导贯穿整个工作台，你可以随时提问，例如：

> 这些论文中，哪些方法适合作为我的对照？
>
> 根据我现有的数据和设备，这个问题应该怎样缩小？
>
> 当前方案还缺少哪些条件，才能进行公平比较？
>
> 这些结果能支持哪部分判断，还有哪些内容不能写进结论？

讨论不会自动替你执行实验或确认结论。需要保存的建议由你决定是否采纳；临时想法也可以随手记入“灵感笔记”。

### 项目进度与恢复

项目总览集中展示当前工作、已有内容与下一步。“任务进度”用于查看后台执行情况，“待确认事项”用于处理需要你审核的节点。

再次进入系统时，在“新建与管理”中选择已有项目，或粘贴项目编号并点击“打开并继续”。当前问题和方案保存在项目中，不只依赖浏览器记忆。

当问题、方法或结果发生修订时，依赖旧内容的记录会提示复核，历史版本仍然保留，帮助你看清研究是怎样一步步变化的。

## 适用场景

目前聚焦三个方向：

- **AI 与机器学习**：方法复现、模型评测、联邦学习、检索增强生成等研究。
- **软件工程与计算机系统**：软件测试、程序分析、系统可靠性与性能评估。
- **计算机安全与隐私**：公开数据、模拟环境或明确授权范围内的安全研究与评测。

适合希望系统推进课程研究、毕业设计、论文复现或小型科研项目的学生、科研入门者与开发者，也适合已经有部分论文、思路或结果，希望继续整理和完善的使用者。

## 项目的核心设计

Scientific Agent 采用 Agent Harness 思路，将模型调用、检索工具、任务编排、人工确认和过程保存组织在一起，为持续的科研工作提供支撑。

- **一条研究主线**：总览、导航、继续入口与科研指导围绕同一个问题和方案衔接。
- **来源与版本留存**：关联文献、方法和结果，修订时保留历史，并提示受影响的下游记录。
- **人机协作推进**：AI 提供检索、分析与整理辅助，由研究者审核重要选择并作出研究判断。

系统辅助你组织研究，不替代研究本身。文献、数据与引用需要核对，实验需要真实执行，最终结论由研究者依据证据确认。
